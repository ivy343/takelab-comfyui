# TakeLab

**이미지의 시작·도착 구도를 눈으로 설계하고, 같은 카메라 레시피를 ComfyUI로 실제 MP4 렌더하는 로컬 촬영 앱입니다.**

ComfyUI Open Source Higgsfield 출품작. 원본을 바꾸지 않는 2D 카메라 합성, 즉시 시점 미리보기, 실제 실행 워크플로 내보내기를 연결했습니다. 생성형 새 각도나 움직이는 피사체를 만들었다고 주장하지 않습니다.

## 할 수 있는 일

- PNG/JPEG/WebP 이미지 업로드, 팬·틸트·다가가기·물러나기 프리셋.
- 시작·도착 중심/확대율, 화면비·시간·fps·easing 조절과 브라우저 미리보기.
- `LoadImage → TakeLabCameraRender`를 실제 ComfyUI 큐에서 실행. 카메라 코어는 GPU와 모델 가중치 없이 CPU로 프레임을 한 장씩 처리합니다.
- H.264 MP4, 시작/중간/끝 PNG, 입력 픽셀 해시와 카메라 레시피, 실제 제출 API 그래프 보관.
- 연결 끊김·노드 누락·실행 실패·접수 불명 구분. 접수 불명은 자동 재접수하지 않습니다.

## 설치

필요: Node.js 22 이상, 실행 가능한 ComfyUI, 해당 ComfyUI Python의 Pillow/NumPy(기존 Comfy 의존성), PATH에 libx264 지원 FFmpeg. 앱 자체에는 npm 의존성이 없습니다. 기존 Comfy/PyTorch 환경을 이 앱 때문에 업그레이드하지 마세요.

1. 이 저장소를 내려받습니다.
2. `custom_nodes/takelab` 폴더를 자신의 `ComfyUI/custom_nodes/takelab`으로 복사합니다. 기존 같은 이름이 있다면 덮지 말고 버전을 확인하세요.
3. FFmpeg 명령이 되는 터미널에서 ComfyUI를 시작합니다. 데스크톱 앱의 PATH가 다르면 Comfy를 시작하기 전에 `TAKELAB_FFMPEG`를 FFmpeg 실행 파일의 절대경로로 지정할 수 있습니다.
4. 저장소 폴더에서 앱을 실행합니다.

PowerShell:

```powershell
$env:COMFY_URL='http://127.0.0.1:8188'
npm start
```

macOS/Linux:

```sh
COMFY_URL=http://127.0.0.1:8188 npm start
```

5. `http://127.0.0.1:4317`을 열고 연결됨 표시를 확인합니다. 포트를 바꾸려면 `PORT`를 설정하세요.

원본 모드에는 SDXL·H3·유료 API·파트너 노드·모델 다운로드가 필요하지 않습니다. ComfyUI는 CPU 모드로도 카메라 노드를 실행할 수 있습니다.

## 사용

예시 또는 자신의 이미지를 고르고, 프리셋과 시작·도착 구도를 조정합니다. 재생으로 미리 확인한 뒤 **ComfyUI로 테이크 만들기**를 누르세요. 완성 영상 아래에서 MP4·실행 워크플로·레시피를 저장합니다.

입력 파일은 바꾸지 않습니다. 앱은 긴 변1024px 이하의 PNG 작업 사본을 만들어 업로드합니다. 카메라 레시피의 파일 SHA256은 그 작업 사본을, 노드의 `source_pixel_sha256`은 디코딩한 RGB8 픽셀을 가리킵니다. 같은 입력/레시피면 카메라 프레임을 재현할 수 있지만 FFmpeg/Pillow 버전이 다를 때 MP4 바이트까지 같다고 보장하지 않습니다.

출력은 자신의 ComfyUI output 디렉터리에 저장됩니다. 앱의 비공개 업로드/작업 기록은 `data/`에 남고 git에서 제외됩니다. 공개 레포에는 자신의 `data/`, 모델 가중치, `.env`, 인증정보를 넣지 마세요.

## 카메라 레시피

```json
{
  "version": 1,
  "width": 768,
  "height": 432,
  "fps": 24,
  "duration": 3,
  "start": {"x": 0.5, "y": 0.5, "zoom": 1},
  "end": {"x": 0.5, "y": 0.5, "zoom": 1.6},
  "easing": "smoothstep"
}
```

중심 x/y=0~1, zoom=1~3. 출력 비율로 cover crop 후 확대하며 경계를 자동 제한합니다. 프레임 수는 `floor(duration*fps+0.5)`, 시작과 도착을 모두 포함합니다(한 프레임이면 시작만). width/height는128~1280의 짝수, duration0.5~8초, fps1~30, 최대240프레임입니다. 최대 경계값 전체를 실제 큰 렌더로 검증한 것은 아닙니다.

## 실제 검증

2026-10-24 Windows 두 PC에서 동일 입력·레시피를 실제 ComfyUI API로 실행했습니다.

| 환경 | 실행 | 확인 결과 |
|---|---|---|
| 회사 ComfyUI0.35.0 / Python3.13.14 / PyTorch2.13.0+cu130 | 768×432,24fps,3초 | H.264/yuv420p,72프레임, 브라우저재생. 해당 실행 Comfy로그4.12초 |
| 집 ComfyUI0.39.0 / Python3.12.6 / PyTorch2.14.1+cu130 / CPU mode | 동일 입력/레시피 | 같은 규격 MP4 생성. 시작·중간·끝 PNG는 회사 출력과 RGB 픽셀 완전 일치 |

카메라 계산/실패정리/실제 작은 MP4 encode·decode 검사20개, Node API/검증/보안/복구 검사5개 통과. 숫자는 해당 환경/샘플 관측이며 속도·무결점 보장이 아닙니다. macOS/Linux 전체 앱 실행은 아직 검증하지 않았습니다.

## 실험: SDXL 호환 모델의 룩 변경

접힌 **빛과 색 바꾸기**는 별도 실험입니다. ComfyUI에 이용 가능한 SDXL 호환 체크포인트가 있으면 img2img→카메라 그래프를 구성합니다. 선택 모델의 이용 조건을 따르며 구조·색·소품이 바뀔 수 있습니다. 임의 체크포인트가 SDXL이라고 자동 판별하지 않습니다.

공식 SDXL Base1.0 다운로드/SHA256 대조는 완료했으나 실제 룩 생성 시험은 PC 메모리 상승으로 중단했습니다. **룩 생성의 성공·시각 품질·속도는 미검증이며 이번 데모/출품의 검증 기능으로 포함하지 않습니다.** 기본 원본 모드를 사용하세요. 영상 모델/모델 보너스 수상을 주장하지 않습니다.

## 문제가 생기면

- 연결 안 됨: COMFY_URL과 Comfy 서버를 확인합니다. 앱은 loopback 전용이며 인터넷 공개 서버로 설계하지 않았습니다.
- 노드 없음: 복사 위치를 확인하고 자신의 ComfyUI를 다시 시작합니다.
- FFmpeg 없음: PATH 또는 TAKELAB_FFMPEG를 지정한 터미널에서 Comfy를 실행합니다.
- 접수 불명: Comfy 큐/기록을 직접 확인하세요. 완료나 실패를 확인하기 전 다시 실행하지 마세요. 앱은 해당 불명 상태를 보존하고 새 접수를 막습니다. 자동 해제 UI는 아직 없습니다. 운영자가 실제 작업을 확인한 뒤 앱을 끄고 해당 `data/jobs/<id>.json` 기록을 별도 보존/이동해야 합니다. 원본 작업과 다른 기록을 삭제하지 마세요.
- 브라우저 새로고침: 마지막 작업 ID로 상태를 다시 확인합니다. 서버 재시작으로 이미 접수된 작업을 다시 보내지 않습니다.
